## R3 (2026-10-20): Check → Bet ×4 money bug, folded-card leak, ×2 clamp

### Root cause of the misclick
`UthScreen.refresh` set the status lines AFTER `super.refresh()` (the kit's relayout). The Dock sizes its action row by the
status width, so each layout used the PREVIOUS state's status. When a street opened, the first decision Dock was laid out
with the short betting status. A few ticks later (the next `local()` / state) the long pre-flop hint pushed the row into
its compact form, and Check moved 42 px with no input (T-B2 run 2: `Check@192+70 → t+3 Check@234+45`). A click aimed at
the first layout landed on another control (the dev run 1: `primary` = Bet ×4). PokerScreen had the same order.

### Fixes
- **Root cause**: both screens call `status(view)` before `super.refresh()` (and again after it, because `apply` resets the timer).
- **Client guard** (`games/poker/present/ClickGuard`, pure, used by `UthScreen` and `PokerScreen`):
  - Each target has an identity: its id, plus its action for the primary and secondary, plus the decision window for
    decisions (UTH `decision_epoch`, poker `legal.seq`).
  - A click is refused when the target under the cursor differs from the one in the last rendered frame.
  - It is also refused within 250 ms (`SETTLE_MS`) of a layout change, unless the layout settled before that change had
    the same control at that point. Keys (Space, Enter, letters) follow the same rule.
  - A refused click does nothing and flashes `poker.v2.reason.moved`.
- **Server**:
  - UTH decisions carry `epoch`. The table keeps `decisionEpoch` (+1 in `openDecisions`) and publishes it as
    `decision_epoch`. A decision with another epoch, or an illegal one, is refused with `uth.v2.reason.stale_decision`
    instead of being silently dropped. A missing `epoch` is still accepted (bots, old tests).
  - Poker's existing `seq` guard now sends `poker.v2.reason.stale_action` instead of returning silently.
- **Leak**: `UthTableBlockEntity.writeClientState` sends another seat's `cards`, `hand` and `best` only when it is
  `you`, or at the showdown when that seat has not folded.
- **×2**: `UthFlow.doubled(v)` doubles the Ante up to its cap, then the Trips under it. If it had to clamp, it flashes
  the same `max_ante` / `max_ante_balance` / `max_trips` reason. The tool turns grey only when it would add nothing.
- Tests:
  - `ClickGuardTest` (3)
  - `UthFlowTest.doubleClampsToTheCapAndSaysWhy`
  - Server `UthV2GameTests.decisionFromAnotherWindowIsRefused`: through `TableNetworking.receive`, stale Bet ×4 and
    Bet ×2 are refused with no chips taken; the right epoch applies.
  - The m10 test now also checks B's `writeClientState` while A is folded.
  - Client `UthRealFlowClientGameTests` round 1: the pre-flop Dock stays put for 15 ticks, and a real click on the primary
    that just became Bet ×4 is refused (server: not decided, play 0, balance unchanged; status says "moved").
  - UTH and poker client tests click only after `clickSettled()`.
