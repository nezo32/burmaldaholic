# V26 — 26.3-only build infrastructure

Owner decision 2026-10-20: Minecraft 26.2 support is dropped; the mod targets 26.3 only.
Scope: build, metadata, CI and docs only. No Java source touched.

## Done
- **Merged `origin/main` into `p2/v26`** (Modrinth publishing, PRs #7 and #8). Those commits only touch
  `.github/workflows/*` (publish-modrinth, reusable-publish-modrinth, modrinth-project-settings, release.yml) and
  `docs/ci/RELEASING.md`. The merge was clean, and without it the Modrinth workflows could not be edited here. The
  feature branch needs this merge before its PR anyway. Local `main` (579564a6, gitignore) is NOT merged; it was
  never pushed.
- `java/gradle.properties`: `mc=26.3`, `supported_mc_versions=26.3`, `supported_mc_range=~26.3` (26.3 plus
  26.3.x patches; Mojang ids are `26.3`, `26.3-rc-N`, so a later `26.3.1` also matches). The `fabric_api_26_2` and
  `modmenu_26_2` entries are removed, so `-Pmc=26.2` now fails fast with "No 'fabric_api_26_2'". The `-Pmc`
  switch is unchanged.
- `fabric.mod.json` (main): unchanged file; `"minecraft": "${mc_range}"` now expands to `~26.3`.
- `build.gradle` and `gradle/linkage-check.gradle`: comments only. `checkLinkage` checks the other supported
  versions, so with 26.3 alone it is skipped through its existing `onlyIf`. It comes back into use when a version
  is added.
- CI and release:
  - `ci.yml` matrix default is `["26.3"]`.
  - `release.yml` CurseForge default is `26.3,Fabric,Java 25,Client,Server`; Modrinth default is `26.3`.
  - `publish-modrinth.yml` default is `26.3`.
  - The description examples in the reusable workflows, the template and `scripts/curseforge-upload.sh` were
    updated. The inlined copy was kept byte-identical.
  - The GitHub repo has no `JAVA_MC_VERSIONS`, `CURSEFORGE_GAME_VERSIONS` or `MODRINTH_GAME_VERSIONS` variables
    (checked with `gh variable list`, repo and env), so the defaults are what runs.
- Docs updated: README.md and README.ru.md (compatibility, install, build, CI), CONTRIBUTING.md,
  docs/architecture/java.md, docs/ci/RELEASING.md, docs/branding/branding.md, and one line in
  REUSABLE_RELEASE_PIPELINE.md. Historical handoff, research and review notes were left as they are.

## For V26b (26.2 shim cleanup; Java only)
- Reflective `GuiGraphicsExtractor.blit` lookups exist because `RenderPipeline` moved packages between 26.2 and
  26.3. On 26.3 alone they can become direct calls:
  - `client/fx/FxSprites.java:60-81`
  - `client/hud/CasinoHud.java:378-398`
  - `client/pvp/kit/Kit.java:20,92-109`
  - `client/table/cards/CardGfx.java:18-39`
  - `client/table/fx/TableGfx.java:17,135-153`
- Runtime key and button numbers (26.2 GLFW vs 26.3 SDL3) in `client/input/Inputs.java:9-10,146-150` and
  `client/ui/v2/V2Input.java:14,42`. Their tests are `InputsTest` (18, 57), `V2InputTest` (14, 21) and
  `RawInputGuardTest` (21-23). The reflective read may stay as a guard, but the 26.2 rationale goes.
- `main/core/table/CasinoTableBlock.java:49`: a `codec()` without `@Override`, kept for 26.2's abstract
  `BaseEntityBlock.codec()`.
- `main/worldgen/CasinoLocator.java:334`: avoids `StructurePlacement` methods (a class on 26.2, an interface on
  26.3). Also the `StructureManager.getStartForStructure` signature split (see `docs/handoff/v013-locate.md:86-87`).
- `main/worldgen/logic/TemplateExporter.java:18`: data version pinned to 26.2's 4903. Consider 26.3's.
- `main/worldgen/logic/CasinoLoot.java:14`: loot JSON/API format differs between 26.2 and 26.3.
- `client/games/slots/client/fx/SlotDraw.java:215`: the `textWithWordWrap` return type changed.
- `client/fx/ClientFx.java:98` and `client/fx/CelebrationOverlay.java:149,465`: the "no HUD blur" workaround
  came from 26.2. Re-check it on 26.3.
- `client/bots/client/BoardAwareTextDisplayRenderer.java:32`: comment only.
- `client/core/mixin/client/CreateWorldGameTabMixin.java:23` and `main/worldgen/CasinoBuilder.java:42`:
  comments only.
- Gametest reflection:
  - `gametest/worldgen/WorldgenSpawnSurvey.java:219-286` (RandomState/climate sampler)
  - `gametest/lastchance/LastChanceGameTests.java:267` (`invulnerableTime` access)
  - `gametest/tables/RealInputClientGameTests.java:43`
  - `gametest/worldgen/LocateGameTests.java:155`
- `docs/architecture/java.md` §1 gotchas describe these shims. Prune them in V26b.

## Risks
- `~26.3` rejects 26.3 pre-releases and release candidates, and 26.4 snapshots, which is intended.
- Any package or agent still running `-Pmc=26.2` will now fail at configuration.
