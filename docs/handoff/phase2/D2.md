## Decision to review (deviation from the PHASE2 acceptance)
There is **no server-side "refuse bets while rolling" gate**. A roll resolves instantly on the server. A chip put down during
the 1.6 s reveal is a legitimate bet on the next roll (no exploit). Refusing it during `REVEAL_DELAY_TICKS` would break
`RealFlowMultiplayerGameTests.crapsTwoHumansPassLineAndPointOn` (Bob bets on the tick the point is set; not D2-owned) and
`CrapsGameTests` (bets right after `roll()`). M5 is gated on the client, which is what R-CDE M5 cites.
`theThrowClosesTheFeltOnTheScreen` proves it on the state the server sends. If the orchestrator wants a server gate, add
`if (table.rollCount() > 0 && gameTime() < revealAt()) { sendError(REASON_ROLLING); return; }` for bet/odds/undo/clear in
`onAction`, and update those two tests.
