# F1: poker real-flow test timing and single-test filtering (paused)

Branch: `fix/poker-realflow-timing` (worktree `E:/projects/mods/minecraft/bw-fix-poker`, based on `v0.2.0-base`).

## Root cause

### Flaky `real_flow_poker_game_tests_realflow_two_humans_play_hands_through_packets`
- The cause is in the test, not the game. The old test bought in at the minimum (40 BB = 80 chips) and called every bet from 3–4 money bots. In some deals both humans bust in hand 2.
- When a human busts, they are removed (`removeFinished` in `endHand`). Once both are gone, the table closes (`afterHumanLeft`) and `hand_no` goes back to 0.
- The success condition `hand_no >= start + 2 && !live` can then never be met, so the test spins until `maxTicks = 3000` and fails with "two hands played on tick 3002". This was seen in a captured trace: the hand-2 river call busted both humans at tick 644/645, and the table sat idle after that.
- Timing was not the problem: a normal run finishes in about 430 ticks.
- Reproduced with `-Dfabric-api.gametest.verify=true` (400 runs): the old test failed **10/400**, the new test failed **0/400**.
- There was also a smaller race. `PokerGameTests.handsRunAgainstBots` and the real-flow test both saved, set and restored the global `poker.botThink*Ticks` config. When they ran in the same batch, one could restore the slow defaults under the other, or leave 0/2 set for the rest of the run.

### `-Dfabric-api.gametest.filter=real_flow_poker` exiting with -1
- The Fabric runner passes the filter to vanilla `GameTestServer`. Vanilla parses it with `ResourceSelectorArgument`, which is an Identifier glob, not a substring match.
- A bare `real_flow_poker` becomes `minecraft:real_flow_poker` and matches nothing. Vanilla then logs "Test selection matcher (...) found no tests" and calls `System.exit(-1)`.
- The filter works if you pass `burmaldaholic-gametest:*real_flow_poker*`.

## Changes
- `java/build.gradle`: a filter value with no `:` is now turned into `burmaldaholic-gametest:*<v>*`, so the documented "substring" usage works. If the value already has wildcards, only the namespace is added. A full `ns:glob` is passed through unchanged. Also forwards `-Dfabric-api.gametest.verify=true` (vanilla's 400x flake check).
- `PokerTableBlockEntity`: no behaviour change. It now exposes the timing constants it already used (`HAND_START_DELAY_TICKS`, `NEXT_HAND_UNCONTESTED_TICKS`, `NEXT_HAND_SHOWDOWN_TICKS`, `WAITING_RETRY_TICKS`), `botThinkCapTicks()` (taken out of `scheduleBot`), and a public `pacing()`.
- `gametest/poker/FastPokerBots`: a reference-counted switch for fast bot thinking. `PokerGameTests.handsRunAgainstBots` and the real-flow test both use it now.
- `RealFlowPokerGameTests`:
  - The humans check, call only small bets (at most 2 BB, and only while at least half the buy-in stays behind), and otherwise fold. Neither can bust.
  - `failIfEver` fails the test straight away, with a trace, if a seat is lost.
  - The tick budget `budgetTicks(2)` is built from the game's own pacing: `PokerBeats.segment` durations, the next-hand delays, and the bot think cap. Right now it comes to 7608. A guard asserts it is at most `MAX_TICKS = 8000`.
  - The failure message includes a per-tick state trace.
